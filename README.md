# Dify私有化部署：从服务器选型到跑通第一条工作流，低预算也能落地

打算把 Dify 装到自己服务器上的人，问的通常是同一个问题的两面：这台机器够不够，以及装完之后能不能真的跑起来。官方给的门槛低得让人意外——2 核 CPU、4GB 内存就能启动——但社区里踩坑的帖子大多不是卡在内存上，而是卡在 80 端口、插件市场超时、以及买错了机房才发现建站要备案。

这篇按实际操作顺序，把配置要求、Docker Compose 流程、常见报错、以及国内几家云服务商里比较省钱的选法讲清楚，最后附上雨云（RainYun）当前在售的云服务器档位和价格，方便直接对着预算挑机器。

## Dify 到底要一台什么样的机器

官方自托管文档里写的最低配置是 **CPU ≥ 2 核、内存 ≥ 4 GiB**，磁盘建议 20GB 起步，实际留 50GB 更稳妥。软件侧要求 Docker 19.03 以上，Docker Compose 必须是 2.24.0 或更新版本——这一条经常被忽略，版本低了 `docker compose up -d` 直接不认新语法。

真正的内存消耗来自容器数量。社区版一次会拉起 7 个核心服务（api、api_websocket、worker、worker_beat、web、plugin_daemon、agent_backend）、8 个依赖组件（weaviate、db_postgres、redis、nginx、ssrf_proxy、agent_ssrf_proxy、sandbox、local_sandbox），外加一个跑完就退出的 init_permissions。加起来十几个容器，2 核 4G 能亮灯，但知识库一建索引、worker 一跑任务，机器就开始喘。

如果目标是内部几百人用的正式环境，Dify 企业版的官方要求直接抬到 **4 核 CPU / 16GB 内存 / 100GB 磁盘**，并且明确写着不支持在 Windows 和 Mac 的 Docker Desktop 上部署，必须是 Linux 服务器。这个差距本身就是个信号：4 核 8G 是社区版比较舒服的落点，再往上就要看你会不会把向量库迁出去独立部署。

## 比内存更容易出事的两件事：线路和备案

Dify 的容器镜像和插件包都在海外，插件市场走的是 `marketplace.dify.ai`。国内机房拉镜像慢、装插件反复超时，是部署阶段最常见的阻塞。有两个方向可以解决。

一是继续用国内机器，但把超时和镜像源改掉。官方 `.env` 里可以调这三个值：


PIP_MIRROR_URL=https://pypi.tuna.tsinghua.edu.cn/simple
PLUGIN_PYTHON_ENV_INIT_TIMEOUT=360   # 默认 120
PLUGIN_MAX_EXECUTION_TIMEOUT=1800    # 默认 600


二是直接选香港或海外节点。镜像、插件、模型 API 都顺畅，代价是访问延迟高一些，适合本来就把 Dify 当内部工具、不对外提供低延迟服务的场景。

还有一条和 Dify 没直接关系但一定会碰上的：国内机房（江苏宿迁、湖北十堰、浙江、广东深圳、重庆等）用域名对外提供服务，80/443 端口需要域名先备案；香港、美国、日本、韩国、德国的机器免备案。如果你只是想给自己团队内网用，不绑域名、直接拿 IP 访问，那备案这一步可以跳过。

## Docker Compose 部署流程

按官方文档走，整条链路是这样的：

bash
# 1. 拉取最新版本源码（需要 git、curl、jq）
git clone --branch "$(curl -s https://api.github.com/repos/langgenius/dify/releases/latest | jq -r .tag_name)" \
  https://github.com/langgenius/dify.git

# 2. 进入 docker 目录，复制环境变量模板
cd dify/docker
cp .env.example .env

# 3. 修改端口（如果服务器上已有 nginx 占用 80）
#    EXPOSE_NGINX_PORT=80      → 改成别的端口
#    EXPOSE_NGINX_SSL_PORT=443

# 4. 启动
docker compose up -d

# 5. 检查容器状态
docker compose ps


容器状态应该是 Up 或 healthy。`init_permissions` 显示 Exited 属于正常，它只负责设置存储目录权限，干完活就退出。

之后浏览器打开 `http://你的服务器IP/install` 创建管理员账号，登录进去第一件事是在插件市场里装模型供应商，配置好 API Key，再跑一条工作流验证端到端是通的。

> 改端口时避开 10080。这个端口不在浏览器默认安全端口列表里，Chrome 会拦，表现出来像是服务挂了，其实是访问不进去。

## 四个高频报错，以及它们的真实原因

**端口冲突。** 报错长这样：`Error starting userland proxy: listen tcp4 0.0.0.0:80: bind: address already in use`。说明机器上已经有 nginx、apache 或者宝塔占了 80，改 `.env` 里的 `EXPOSE_NGINX_PORT` 即可。

**插件一直下载失败。** 除了上面说的镜像源和超时参数，如果你用的是国内机器且没有代理，建议把插件安装放在部署稳定之后再集中处理，先确认核心对话功能可用。

**升级后配置对不上。** Dify 在企业版 3.10 之后重构了环境变量结构，`.env.example` 被拆成了精简主文件加 `envs/*.env.example` 的可选分组。社区版同样建议每次升级后把新的 `.env.example` 和自己的 `.env` 逐项对比，尤其注意新版新增了哪些必须的服务，别沿用旧的 `docker-compose.yaml`。

**版本安全。** 2026 年初的 React / Next.js 远程执行漏洞波及了一批同类产品，Dify 在 v1.11.1 里才完成修复。私有化部署的好处是数据在自己手里，坏处是补丁也得自己打，别装完就放着不管。

## 三个容易买错的点

**NAT 还是独立 IP。** 雨云不少机型默认是 NAT 模式，共用公网 IP、可开 10 个端口映射，适合学习、内网穿透、跑程序。但 Dify 要对外提供 Web 访问，NAT 机型需要额外加购独立公网 IP（普通机房 5 元/月，带防御的机房价格更高），下单时确认一下机型说明。国内机房的独立 IP 往往还自带防御，比如宿迁是独享 150G、湖北十堰独享 100G。

**别只看 CPU 核数。** 雨云的 CPU 型号分 Xeon E5v2、E5v3、E5v4、EPYC 7702、Xeon Gold、Xeon Platinum 等，性能排序基本是 Platinum > Gold > EPYC 7702 > E5v4 > E5v3 > E5v2，价格也按这个顺序走。同样标 4 核 8G，跑向量检索和跑闲聊的体验差别不小，能选 Gold 或 EPYC 就别省那几块钱。

**云盘要留量。** Dify 的 PostgreSQL、Redis 和向量库数据都落在本地盘上，知识库导入几百份文档之后磁盘涨得比想象中快。雨云的云盘支持按需扩容，一开始就按 50GB 以上规划更省事。

## 花多少钱最合适：三种典型场景

**个人学习和验证功能。** 2 核 4G 够用，配合官方最低要求刚好达标。选香港或美国线路省掉备案和镜像加速的麻烦。这一档里美国标准版 ￥34/月、香港标配版 ￥35/月是性价比比较高的两个入口。

**小团队内部使用（5–20 人）。** 直接上 4 核 8G。多出来的内存主要给 worker 和向量库，知识库索引、批量任务并行的时候不会卡住整个面板。美国高配版 ￥113/月、香港顶配版 ￥108/月，或者香港二区折后 74.48 元/月这种。

**正式生产环境。** 按企业版的 4 核 16G 起，磁盘 100GB 以上，配独立 IP。到这一步建议把数据库和向量库拆到独立实例，Dify 本身只跑应用层容器。

## 常见问题

**2 核 4G 真的能跑 Dify 吗？**
能启动，能跑通对话。但知识库索引和批量任务会明显吃紧，如果准备长期用，别在这上面省 20 块钱。

**需要 GPU 吗？**
Dify 本身是应用编排层，不跑模型权重。除非你要在同一台机器上部署本地大模型（Ollama 之类），否则纯 CPU 机器就够。真要本地跑 8B 模型，显存需求远超过内存需求，那不是云服务器该解决的问题。

**国内机器和香港机器怎么选？**
要低延迟、面向国内用户、域名已备案，选国内机房（宿迁、十堰、宁波、深圳等）；不想折腾备案和镜像加速，选香港或海外。做 Dify 内部工具，第二类往往更省心。

**社区版和企业版差在哪？**
最直观的是资源门槛：2 核 4G 对 4 核 16G，而且企业版不支持在 Windows/Mac 的 Docker Desktop 上跑。功能层面的差异以官方企业版文档为准，别拿社区版的部署经验去套企业版。

**装完发现跑不动，能换配置吗？**
雨云的云服务器支持按天补差价升级套餐、扩容云盘、迁移机房，不用重新买一台。所以第一台机器买低一点、一个月内按需往上升，是更省钱的路径。
